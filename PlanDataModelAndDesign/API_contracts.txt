1. AUTHENTICATION PROVIDERS SERVICE
Endpoint: /api/auth-providers
-------------------------------------------------------------------------------

[POST /api/auth-providers]
- Description: Creates a new authentication source (e.g., Google, GitHub, Internal).
- Request Body: { "name": "string" }
- Success Response (201 Created): { "id": 1, "name": "string" }
- Error Response (400 Bad Request): "Provider name already exists or invalid data"

[GET /api/auth-providers]
- Description: Lists all registered authentication providers.
- Success Response (200 OK): Array of provider objects.

[PUT /api/auth-providers/{id}]
- Description: Updates the name of an existing provider.
- Request Body: { "name": "string" }
- Success Response (200 OK): Updated provider object.

[DELETE /api/auth-providers/{id}]
- Description: Removes a provider.
- Constraint: Blocked if active users are linked to this provider.
- Success Response (204 No Content).

2. ROLES SERVICE
Endpoint: /api/roles
-------------------------------------------------------------------------------

[POST /api/roles]
- Description: Registers a new system role for access control (e.g., Admin, Editor).
- Request Body: { "name": "string", "description": "string" }
- Success Response (201 Created): Role object with generated ID.

[GET /api/roles]
- Description: Retrieves all available roles.
- Success Response (200 OK): Array of role objects.

[PUT /api/roles/{id}]
- Description: Updates the name or description of an existing role.
- Request Body: { "name": "string", "description": "string" }
- Success Response (200 OK): Updated role object.

[DELETE /api/roles/{id}]
- Description: Removes a role. 
- Constraint: Cannot delete if assigned to users (RBAC Integrity).
- Success Response (204 No Content).

-------------------------------------------------------------------------------
3. USERS SERVICE
Endpoint: /api/users
-------------------------------------------------------------------------------

[POST /api/users]
- Description: Registers a new user. Passwords hashed via Bcrypt (12 rounds).
- Request Body: { "name": "string", "email": "user@example.com", "password": "...", "provider_id": integer }
- Success Response (201 Created): User object (excluding password_hash).

[GET /api/users]
- Description: Paginated list of all users.
- Success Response (200 OK): Array of user objects.

[PUT /api/users/{id}]
- Description: Updates user metadata (name, email, or provider).
- Success Response (200 OK): Updated user object.

[DELETE /api/users/{id}]
- Description: Deletes a user account.
- Success Response (200 OK): { "message": "User deleted successfully" }

[POST /api/users/assign-role]
- Description: Links a user to a specific role in the junction table.
- Request Body: { "users_id": integer, "roles_id": integer }
- Success Response (200 OK): { "message": "Role assigned successfully" }

[DELETE /api/users/{id}/roles/{roleId}]
- Description: Revokes a specific role from a user.
- Success Response (200 OK): { "message": "Role revoked successfully" }

[GET /api/users/{id}/profile]
- Description: Retrieves full user profile including Role and Auth Provider details via JOINs.
- Success Response (200 OK): Full profile object.

-------------------------------------------------------------------------------
4. TASKS SERVICE
Endpoint: /api/tasks
-------------------------------------------------------------------------------

[GET /api/tasks]
- Description: List all tasks where is_active = true.
- Success Response (200 OK): Array of active task objects.

[POST /api/tasks]
- Description: Create task with Smart Priority (Keywords: URGENT, CRITICAL).
- Rules: Title min 10 chars. Status cannot start as COMPLETED.
- Success Response (201 Created).

[PUT /api/tasks/{id}]
- Description: Update task fields.
- Logical Cascade: If is_active is set to false, all task_schedules.end_date = NOW().
- Success Response (200 OK).

[DELETE /api/tasks/{id}]
- Description: Hybrid Delete Strategy. 
- Hard Delete: Empty/Draft tasks.
- Soft Delete: Tasks with content (archives via is_active = false).
- Success Response (200 OK).

-------------------------------------------------------------------------------
5. TASK SCHEDULES SERVICE
Endpoint: /api/tasks/{taskId}/schedules
-------------------------------------------------------------------------------

[POST /api/tasks/{taskId}/schedules]
- Description: Adds a new recurrence rule to a task (1:N relationship).
- Request Body: { "frequency": "string", "days_of_week": "int[]", "start_date": "ISO-Date" }
- Success Response (201 Created).

[GET /api/tasks/{taskId}/schedules]
- Description: Lists all active schedules for a specific task.
- Success Response (200 OK).

[DELETE /api/schedules/{id}]
- Description: Removes a specific schedule without affecting the parent task.
- Success Response (204 No Content).

-------------------------------------------------------------------------------
HTTP STATUS CODES SUMMARY
-------------------------------------------------------------------------------
200 OK - Successful operation (Read, Update, Delete)
201 Created - Resource created successfully
204 No Content - Successful deletion with no body
400 Bad Request - Business rule violation / Invalid data
404 Not Found - Resource not found
500 Internal Error - Database connection failure or unexpected error
